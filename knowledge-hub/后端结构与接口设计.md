# knowledge-hub 后端结构与接口设计（前端对接文档）

> 本文档供前端同学设计界面与联调使用，涵盖后端架构、配置、统一响应、鉴权、数据模型、全部接口的请求/响应示例，以及前端需要特别注意的点。

---

## 一、后端整体架构

### 1. 多模块划分（7 个模块）

| 模块 | 职责 |
|------|------|
| `knowledge-common` | 统一返回 `Result`、异常、常量（`DocConst`、`StorageConst`） |
| `knowledge-framework` | JWT、Redis、MyBatis-Plus、全局异常、拦截器、MinIO、`@RequireLogin`/`@RequireAdmin` 注解 |
| `knowledge-account` | 用户、角色、权限、登录/登出 |
| `knowledge-doc` | 文档、分类、标签、注释、收藏、举报、切片、文件存储 |
| `knowledge-ai` | AI 对话（非流式/多轮/流式）、会话 |
| `knowledge-search` | 关键词搜索、搜索历史 |
| `knowledge-server` | 启动入口 + 配置文件 |

依赖是**单向**的，前端无需关心，只需知道接口在哪即可。

### 2. 单模块内部分层

```
com.knowledgehub.<模块>
├── controller/   # 接口层：收参数、调 Service、返回 Result
├── service/      # 业务接口
│   └── impl/     # 业务实现
├── mapper/       # MyBatis-Plus Mapper
├── entity/       # 数据库表对应的实体
├── dto/          # 请求参数对象
├── vo/           # 响应对象（给前端的数据）
├── config/       # 配置类
├── annotation/   # 自定义注解（@RequireLogin / @RequireAdmin）
├── context/      # 当前登录用户上下文（UserContext）
└── jwt/          # JWT 工具 + 黑名单工具
```

请求处理链路：`Controller`（收参、鉴权）→ `Service`（业务）→ `Mapper`（数据库）。

## 三、统一响应格式

所有接口返回统一结构 `Result<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

### 错误码（业务 code，注意：HTTP 状态码目前统一是 200）

| code | 含义 | 前端处理 |
|------|------|----------|
| 200 | 成功 | 正常 |
| 400 | 参数错误 | 提示 message |
| 401 | 未登录 / 登录失效 | 跳转登录页 |
| 403 | 无权限 | 提示"无权限" |
| 500 | 业务失败 / 系统异常 | 提示 message |

> ⚠️ 后端目前所有响应 **HTTP 状态码都是 200**，业务成败看 body 里的 `code` 字段。前端 axios 拦截器应判断 `response.data.code`，而不是 `response.status`。

**分页结构**（MyBatis-Plus `Page`）：

```json
{
  "records": [ ...列表... ],
  "total": 2,
  "size": 10,
  "current": 1,
  "pages": 1
}
```

字段：`records`（当前页数据数组）、`total`（总条数）、`size`（每页条数）、`current`（当前页码，从 1 开始）、`pages`（总页数）。

**时间格式**：所有时间字段是 ISO-8601 字符串，如 `"2026-09-23T11:08:57"`（前端直接当字符串处理或 `new Date()` 解析）。

## 四、鉴权机制

### 1. 登录流程

1. `POST /api/auth/login` 传 `{username, password}`。
2. 成功返回 `data.token`（JWT）和 `data.user`（用户信息）。
3. 前端把 token 存 `localStorage`（或 pinia）。

### 2. 请求携带 token

所有需要登录的接口，在请求头加：

```
Authorization: Bearer <token>
```

### 3. 登出

`POST /api/auth/logout`（带 token）后，token 会进入 Redis 黑名单，立即失效。前端登出后应清除本地 token 并跳登录页。

### 4. 前端全局拦截器建议

- **请求拦截器**：给每个请求加 `Authorization` 头。
- **响应拦截器**：判断 `data.code`：
  - `code === 401` → 清 token，跳登录页；
  - `code === 403` → 提示无权限；
  - `code !== 200` → 提示 `message`。

### 5. 权限分级

| 级别 | 注解 | 说明 |
|------|------|------|
| 公开 | 无 | 游客可访问（列表、详情、搜索、分类/标签查询、登录/注册） |
| 登录 | `@RequireLogin` | 需带 token（上传、编辑、删除、注释、收藏、举报、AI 问答） |
| 管理员 | `@RequireAdmin` | 需 ADMIN 角色（分类管理、举报处理等） |

前端根据 `user.role` 判断是否显示管理员菜单。

## 五、数据模型（前端需要了解的字段）

### 1. 用户 `sys_user`（登录返回的 user）

```json
{
  "id": 1,
  "username": "admin",
  "nickname": "管理员",
  "avatar": null,
  "role": "ADMIN"   // "ADMIN" 管理员 / "USER" 普通用户
}
```

### 2. 文档列表项 `DocListVO`

```json
{
  "id": 1,
  "title": "SpringBoot 与 Mybatis",
  "summary": "摘要",
  "categoryName": "Spring Boot",   // 分类名（可能为 null）
  "uploaderName": "管理员",
  "viewCount": 12,
  "favoriteCount": 3,
  "createTime": "2026-09-23T11:08:57"
}
```

### 3. 文档详情 `DocDetailVO`

```json
{
  "id": 1,
  "title": "SpringBoot 与 Mybatis",
  "summary": "摘要",
  "content": "# 这是 Markdown 原文...",   // 渲染成 HTML 展示
  "categoryId": 2,
  "categoryName": "Spring Boot",
  "tags": "Spring,Mybatis",           // 逗号分隔字符串
  "uploaderId": 1,
  "uploaderName": "管理员",
  "sourceType": "UPLOAD",             // PRESET 预置 / UPLOAD 用户上传

  "fileSize": 71,
  "viewCount": 12,
  "favoriteCount": 3,
  "createTime": "2026-09-23T11:08:57",
  "updateTime": "2026-09-23T11:08:57",
  "favorited": false,                 // 当前用户是否已收藏（未登录永远 false）
  "annotations": []                   // 注释列表（当前阶段为空数组）
}
```

### 4. 分类 `Category`

```json
{ "id": 1, "name": "Spring Boot", "sort": 1, "createTime": "..." }
```

### 5. 标签 `Tag`

```json
{ "id": 1, "name": "Spring", "createTime": "..." }
```

### 6. 注释 `Annotation`

```json
{
  "id": 1,
  "docId": 1,
  "userId": 2,
  "userName": "张三",
  "content": "这里的说法可以补充一下...",
  "type": "SUPPLEMENT",    // SUPPLEMENT 补充 / CORRECTION 纠错 / QUESTION 提问
  "status": 1,
  "createTime": "..."
}
```

### 7. AI 会话 `Conversation`

```json
{ "id": 3, "userId": 1, "docId": null, "title": "What is Spring Boot?", "createTime": "...", "updateTime": "..." }
```

`docId` 为 null 表示全局问答，非 null 表示某篇文档的问答。

### 8. AI 消息 `Message`

```json
{ "id": 1, "conversationId": 3, "role": "user", "content": "问题...", "createTime": "..." }
```

`role`：`user`（用户）/ `assistant`（AI 回答）/ `system`。

## 六、全部接口详解

### （一）认证 Auth

#### 1. 注册
```
POST /api/auth/register
Content-Type: application/json
```
请求体：
```json
{ "username": "zhangsan", "password": "123456", "nickname": "张三" }
```
响应：`Result<Void>`，成功 `data: null`。失败（用户名已存在）`code:500`。

#### 2. 登录
```
POST /api/auth/login
```
请求体：
```json
{ "username": "admin", "password": "123456" }
```
响应：
```json
{
  "code": 200,
  "data": {
    "token": "eyJhbGciOi...",
    "user": { "id": 1, "username": "admin", "nickname": "管理员", "avatar": null, "role": "ADMIN" }
  }
}
```

#### 3. 登出
```
POST /api/auth/logout
Authorization: Bearer <token>
```
响应：`data: null`。

#### 4. 当前用户信息
```
GET /api/user/info
Authorization: Bearer <token>
```
响应：`data` 为 UserVO（见五.1）。

### （二）文档 Doc

#### 1. 分页列表（公开）
```
GET /api/doc/page?page=1&size=10&title=xxx&categoryId=2&uploaderId=1
```
参数都可选：`page`、`size`、`title`（标题模糊）、`categoryId`、`uploaderId`。
响应：`data` 为 `Page<DocListVO>`。

#### 2. 关键词搜索（公开，同 doc 搜索）
```
GET /api/doc/search?keyword=Spring&page=1&size=10
```
响应：`Page<DocListVO>`。标题命中的排前面。

#### 3. 文档详情（公开，浏览量 +1）
```
GET /api/doc/{id}
```
响应：`data` 为 `DocDetailVO`。

#### 4. 上传文档（登录）
```
POST /api/doc/upload
Content-Type: multipart/form-data
```
表单字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| `file` | File | .md 文件（必填） |
| `title` | String | 标题（必填） |
| `summary` | String | 摘要（可选） |
| `categoryId` | Long | 分类 ID（可选） |
| `tags` | String | 标签，逗号分隔（可选） |

响应：`data` 为新文档的 `docId`（Long）。

#### 5. 编辑文档（登录，本人或管理员）
```
PUT /api/doc/{id}
Content-Type: application/json
```
请求体：
```json
{ "title": "新标题", "summary": "新摘要", "categoryId": 2, "tags": "Spring,Java" }
```
响应：`data: null`。

#### 6. 删除文档（登录，本人或管理员，软删除）
```
DELETE /api/doc/{id}
```
响应：`data: null`。

#### 7. 下载文档（公开）
```
GET /api/doc/{id}/download
```
响应：文件流（`Content-Type: application/octet-stream`，`Content-Disposition: attachment; filename*=UTF-8''xxx.md`）。
前端可用 `window.open(url)` 或 `<a href>` 直接触发下载。

### （八）AI 问答 Ai

#### 1. 全局问答（非流式，登录）
```
POST /api/ai/chat
Content-Type: application/json
```
请求体：
```json
{ "message": "什么是 Spring Boot？", "conversationId": null }
```
`conversationId` 可选：传 null 会新建会话；传上次返回的 id 会续接同一会话（多轮上下文）。
响应：
```json
{
  "code": 200,
  "data": { "conversationId": 3, "answer": "Spring Boot 是..." }
}
```

#### 2. 文档问答（非流式，登录）
```
POST /api/ai/chat/doc
```
请求体：
```json
{ "docId": 2, "message": "这篇文档讲了什么？", "conversationId": null }
```
响应同上（`ChatResponseVO`）。

#### 3. 全局问答（流式 SSE，登录）
```
POST /api/ai/chat/stream
Content-Type: application/json
Accept: text/event-stream
```
请求体同非流式。
响应：SSE 流，逐 token 推送，每个 `data:` 是一小段文本。

#### 4. 文档问答（流式 SSE，登录）
```
POST /api/ai/chat/doc/stream
```
同上。

> ⚠️ **流式接口前端怎么接**：用 `fetch` + `ReadableStream` 逐段读（不要用 `EventSource`，因为它不支持自定义 Header、也不支持 POST）。示例见第七节。

#### 5. 会话列表（登录）
```
GET /api/ai/conversation/list
```
响应：`List<Conversation>`（按更新时间倒序）。

#### 6. 会话消息（登录）
```
GET /api/ai/conversation/{id}/messages
```
响应：`List<Message>`（按时间正序）。

#### 7. 删除会话（登录，本人）
```
DELETE /api/ai/conversation/{id}
```
响应：`null`。

## 七、前端需要特别注意的点

### 1. 流式 SSE 读取（fetch + ReadableStream）

```javascript
async function streamChat(message, conversationId) {
  const resp = await fetch('/api/ai/chat/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer ' + token,
    },
    body: JSON.stringify({ message, conversationId }),
  });
  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  let fullText = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    const chunk = decoder.decode(value, { stream: true });
    // 每个 chunk 形如 "data:xxx\n\n"，去掉 "data:" 前缀就是 token 文本
    fullText += chunk.replace(/^data:/gm, '').replace(/\n\n/g, '');
    // 实时更新到界面上（打字机效果）
    appendToChat(fullText);
  }
}
```

### 2. 文件上传（multipart）

```javascript
const formData = new FormData();
formData.append('file', file);
formData.append('title', title);
formData.append('summary', summary);
formData.append('categoryId', categoryId);
formData.append('tags', tags);
await axios.post('/api/doc/upload', formData, {
  headers: { 'Authorization': 'Bearer ' + token }  // 不要手动设 Content-Type，让浏览器自动带 boundary
});
```

### 3. 下载文档

```javascript
// 简单方式（带 token 的情况需要手动加 header，推荐用 axios blob 下载）
const resp = await axios.get(`/api/doc/${id}/download`, { responseType: 'blob' });
// 从 Content-Disposition 或自定义文件名生成 a 标签下载
```

> 注意：下载接口是公开的，但如果要带 token（记录下载用户），用 axios 并带 header。

### 4. Markdown 渲染

详情页的 `content` 是 Markdown 原文，前端用 `marked` + `highlight.js` 渲染成 HTML 展示。

### 5. 权限控制前端表现

- `user.role === 'ADMIN'`：显示管理菜单（分类管理、举报处理）。
- 文档详情页：`favorited` 字段决定收藏按钮状态。
- 编辑/删除按钮：仅当 `uploaderId === 当前用户 id` 或 `role === 'ADMIN'` 时显示。

### 6. 多轮对话的 conversationId 传递

- 第一次 `chat` 传 `conversationId: null`，拿到返回的 `conversationId`。
- 后续追问带上这个 id，AI 才有上下文记忆。
- 会话列表（`/api/ai/conversation/list`）里每个会话有 `id`，点进去用 `/messages` 拉历史。

## 九、本地联调清单

1. 后端已启动：`http://localhost:8081/api/ping` 返回 `pong`。
2. 登录拿 token：`POST /api/auth/login`（admin / 123456）。
3. 前端 axios 的 `baseURL` 设为 `http://localhost:8081`（或配 vite proxy 到 8081）。
4. CORS 后端已全局放开（`allowedOriginPatterns("*")` + `allowCredentials(true)`），前端可直接跨域调；若走 vite proxy 则无需关心。
